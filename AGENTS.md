# Agent instructions

## Design skills

For any design decision or visual change (layout, type, colour, spacing, components, copy on the page, motion), load and follow these three skills before making changes:

1. **`emil-design-eng`**: Emil Kowalski's approach to UI polish and the small details. This is the main reference for **animation and motion**. Use his related motion skills too:
   - `animate` to build new motion
   - `review-animations` / `improve-animations` to critique or audit existing motion
   - `animation-performance` when motion is janky or drops frames
   - `find-animation-opportunities` to find places that could use motion
2. **`impeccable`**: critique, audit, polish, hardening, accessibility, responsive behaviour and UX copy.
3. **`design-taste-frontend`** (Taste): art direction and the no-slop house style for the public-facing pages.

The skills take priority over `DESIGN.md` and `PRODUCT.md`. If the skills disagree with each other, use Emil Kowalski's skills for motion. For anything the skills don't cover, follow `DESIGN.md` and `PRODUCT.md`.

## Project context

- `DESIGN.md`: the visual system (type, colour, layout). Read it before any design change and keep it up to date.
- `PRODUCT.md`: audience, positioning and content rules.
- `.impeccable/`: saved Impeccable output (e.g. critiques).
